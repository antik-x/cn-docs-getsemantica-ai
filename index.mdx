你的 AI 智能体刚刚做出了一个决策。现在，需要有人能把它解释清楚。

*它当时知道什么？哪些事实影响了结果？这些事实从何而来？它以前是否做过同样的判断——结果如何？*

如果你的技术栈无法以可追溯的记录回答这些问题，你就存在一个缺口。不是能力缺口，而是**问责缺口**。这正是 AI 至今未能在医疗、金融、法律和政府领域规模化落地的原因，也是面向这些市场构建产品的团队不断从零重建同样护栏的原因。

**Semantica 弥合的正是这个缺口。**它是位于你现有智能体框架之下的上下文与问责层：不是用来取代 LangChain 或 LlamaIndex，而是让它们的输出变得可信的基础设施。


## 每个生产环境 AI 团队都会遇到的问题

强大的智能体并不天然可信。五个结构性盲区让现代 AI 系统无法在受监管的环境中部署：

**没有记忆结构**——智能体存储的是嵌入（Embedding），而非语义
- 无法追问一条事实*为什么*会被召回
- 被召回的事实与其源文档之间没有关联
- 上下文是一个黑盒，每次运行都会重置

**没有决策轨迹**——智能体持续行动，却不记录任何东西
- 没有可供提交给监管者或审计师的历史
- 无法回放或复现过去的决策
- 调试意味着重新运行，而非回顾检查

**没有溯源（Provenance）**——输出无法追溯到源事实
- 在医疗、金融和法律领域：这是硬性的合规阻碍
- 从推理回溯到原始文档没有数据血缘
- 无法证明智能体实际依赖了什么

**没有推理透明度**——只有黑盒答案，没有解释
- 无法校验推理路径
- 无法质疑某个具体结论
- 没有改进或纠正未来行为的依据

**没有冲突检测**——相互矛盾的事实悄悄共存在向量存储中
- 两个来源不一致时无从察觉
- 输出随时间推移变得不一致且不可预测
- 随着知识库增长，静默失败不断累积

<Note>
  这些并非边缘案例。它们正是企业 AI 试点停滞不前的原因，也是你的合规团队一直说*还没到时候*的原因。
</Note>


## Semantica 为你的技术栈带来什么

Semantica 为每个智能体提供实现问责所需的基础设施。几分钟即可接入你现有的环境：

**上下文图谱（Context Graph）**——一张结构化、可查询的图谱，记录你的智能体知道什么、决策了什么、推理了什么
- 跨智能体运行持久存在：会话之间不丢失上下文
- 可用 SPARQL 和完整的图算法查询
- 节点和边带有 `valid_from` / `valid_until` 的时序模型
- 完整知识状态的时间点快照

**决策智能**——每个决策都是你系统中的一等对象
- `record_decision()` 捕获完整生命周期与因果链
- 对过往决策进行混合先例检索，保证一致性
- `analyze_decision_impact()` 展示下游后果
- 从触发到结果的因果链可视化

**全链路溯源**——每条事实都链接到其源文档和摄取事件
- 跨所有模块的 W3C PROV-O 兼容血缘
- 从原始输入到最终推理的完整可追溯性
- 带 `recorded_at` 时间戳并支持 OWL-Time 导出
- 满足 HIPAA、SOX、GDPR、FDA 21 CFR Part 11 的审计要求

**推理引擎**——可解释的推理路径，而非黑盒
- 前向链、Rete、演绎、溯因
- 基于 SPARQL 查询的 RDF 图推理
- 支持递归 Horn 子句规则的 Datalog
- 每个结论都有可追溯的推导路径支撑

**时序智能**——你的图谱不仅知道*什么*，还知道*何时*
- Allen 区间代数：涵盖全部 13 种时序关系
- 对历史图谱状态的时间点查询
- 每条事实都带时序溯源标记
- 支持 OWL-Time 导出，符合标准的归档

**Ontology Hub**——在浏览器中完成本体的完整生命周期
- 用于 Schema 设计与编辑的可视化编辑器
- SHACL Studio 用于编写约束和校验
- 跨多个本体的对齐编写
- 内置健康仪表盘与版本控制

<Tip>
  可与任何大语言模型（LLM）提供商和任何智能体框架协同工作：无需改动架构，即可加入现有技术栈。
</Tip>

```python OpenAI
from semantica.context import AgentContext, ContextGraph
from semantica.vector_store import VectorStore
from semantica.llms import OpenAI

context = AgentContext(
    vector_store=VectorStore(backend="faiss", dimension=1536),
    knowledge_graph=ContextGraph(advanced_analytics=True),
    decision_tracking=True,
    llm=OpenAI(model="gpt-4o"),
)

context.store("GPT-4 outperforms GPT-3.5 on reasoning benchmarks by 40%")

decision_id = context.record_decision(
    category="model_selection",
    scenario="Choose LLM for production reasoning pipeline",
    reasoning="GPT-4 benchmark advantage justifies 3x cost increase",
    outcome="selected_gpt4",
    confidence=0.91,
)

precedents = context.find_precedents("model selection reasoning", limit=5)
influence  = context.analyze_decision_influence(decision_id)
```

## 为错误代价高昂的领域而生

Semantica 专为这样的领域而设计：每个决策都必须可解释，每条事实都必须可追溯。

<Warning>
  **这是系统级的可解释性，而非基础模型的可解释性。**Semantica 不会暴露、重构或解释大语言模型（LLM）/基础模型*内部*发生了什么——其内部推理或思维链对外保持不透明，对任何外部系统而言都是如此。Semantica 解释的是模型*之外*的东西：输入的上下文与数据、产生的决策、其溯源、相关关系、所应用的策略，以及完整的执行轨迹。完整范围说明见[核心概念](concepts)。
</Warning>

**医疗与生命科学**

- 每一行代码你的安全团队都可审计

- 无框架锁定：可与任何智能体技术栈配合使用
