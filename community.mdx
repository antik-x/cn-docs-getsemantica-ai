Semantica 以公开方式构建，贡献者来自众多领域的研究者、工程师与从业者。无论是提交 bug、分享项目还是评审 PR——你都是这个生态的一分子。


## 获取帮助

- [GitHub Issues](https://github.com/semantica-agi/semantica/issues) —— 提交带完整上下文的 bug 报告与功能请求。
- [GitHub Discussions](https://github.com/semantica-agi/semantica/discussions) —— 提问、分享想法并讨论设计决策。
- [Pull Requests](https://github.com/semantica-agi/semantica/pulls) —— 浏览开放的贡献并提交你自己的。
- [安全问题](https://github.com/semantica-agi/semantica/security/advisories/new) —— 以私密方式报告漏洞：切勿通过公开 issue 报告。


## 社区准则

我们遵循 [Contributor Covenant 行为准则](https://github.com/semantica-agi/semantica/blob/main/CODE_OF_CONDUCT.md)。社区建立在四项原则之上：

- **尊重**：以善意和耐心对待每个人，无论经验水平如何
- **包容**：欢迎各种背景、领域与方法
- **协作**：共同追求更好的方案，而不是在方法上互相竞争
- **学习**：开放地分享知识，毫无顾虑地提问，帮助他人成长

如需报告不可接受的行为，请以 `[CoC]` 为前缀开一个 GitHub issue。每一份报告都会被调查。


## 贡献方式

贡献没有唯一正确的方式。选择适合你技能与时间的路径：

### 代码

- 修复带 [`good-first-issue`](https://github.com/semantica-agi/semantica/labels/good-first-issue) 标签的开放 bug
- 添加新功能或新集成
- 改进性能或重构现有模块

### 文档

- 修正指南中的错别字并提升表达清晰度
- 为 API 参考添加示例
- 编写领域专属的实战手册 notebook

### 测试

- 为未测试的模块补充覆盖率
- 复现并确认已报告的 bug
- 提升测试在各平台上的可靠性

### 社区

- 在 issue 和讨论中回答问题
- 评审开放的 pull request
- 在 GitHub Discussions 中分享你的 Semantica 项目

完整的开发工作流见[贡献指南](contributing-guide)。
