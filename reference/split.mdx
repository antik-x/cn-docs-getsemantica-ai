**`semantica.split`** 将文档切分为**能保留语义上下文**的文本块：

- 六种分块策略：递归、语义、实体感知、关系感知、滑动窗口、结构
- `SemanticChunker` 基于嵌入（Embedding）的主题切换检测，只在内容真正变化时才切分
- `EntityAwareChunker` 让实体提及在文本块边界处保持完整
- `RelationAwareChunker` 将主谓宾三元组保持在单个文本块内
- 分块质量直接决定下游嵌入的准确率与实体抽取质量


## 分块为何重要

大多数大语言模型（LLM）和嵌入模型都有固定的上下文窗口。超过窗口大小的文档必须切分。但朴素的切分方式（每 500 个字符切一次，不管结构）会破坏语义上下文：

- 像「Apple Inc.」这样的实体提及被切到两个文本块后，在两边都失去了上下文
- 像「Steve Jobs founded Apple」这样的关系三元组若在「Steve Jobs」处被切开，就会留下悬空的主语
- 对混合了两个不相关主题的文本块做嵌入，得到的质心向量与哪个主题都对不上

Semantica 的分块方法正是为避免这些失败模式而设计的。

## 导出类

| 类 | 作用 |
| :--- | :--- |
| `TextSplitter` | 统一入口：更换 `method=` 无需改动下游代码 |
| `Chunk` | `{text, start_index, end_index, metadata, id}` |
| `SemanticChunker` | 基于嵌入的主题切换检测：只在内容真正变化时才切分 |
| `StructuralChunker` | 基于标题/章节的切分，依靠结构化文本分析 |
| `EntityAwareChunker` | 防止命名实体提及被切分到文本块边界两侧 |
| `RelationAwareChunker` | 将主谓宾三元组完整保留在单个文本块内 |
| `HierarchicalChunker` | 多级分块，产生父/子文本块关系 |

**`TextSplitter` 可用的 `method=` 取值：**

| 方法 | 适用场景 |
| :--- | :--- |
| `recursive` | 通用文本：按段落、句子、词语的顺序切分 |
| `sentence` | 对话文本、问答 |
| `paragraph` | 重视段落完整性的长篇文本 |
| `token` | LLM 上下文窗口约束 |
| `semantic_transformer` | 存在主题切换的长文档 |
| `entity_aware` | KG 抽取流水线 |
| `relation_aware` | 重视三元组完整性的 KG 流水线 |
| `structural` | 具有标题/段落结构的文本 |
| `sliding_window` | 面向双编码器检索的稠密重叠 |

## 你将获得

- **TextSplitter** —— 11 种分块策略的统一接口：更换方法无需改动下游代码。
- **语义分块** —— 基于嵌入的主题切换检测：只在主题真正变化时才切分。
- **实体感知分块** —— 实体跨度绝不跨越文本块边界：由边界调整来保证。
- **关系感知分块** —— 主谓宾三元组保留在单个文本块内，服务于 KG 流水线。
- **Chunk 对象** —— 输出数据类，包含文本、字符偏移量、可选 id 与方法特定的元数据。

## 快速开始

<Steps>
  <Step title="选择切分方法">
    ```python
    from semantica.split import TextSplitter

    splitter = TextSplitter(
        method="recursive",   # see Splitting Methods table
        chunk_size=1000,
        chunk_overlap=200,
    )
    ```
  </Step>
  <Step title="切分原始文本">
    ```python
    chunks = splitter.split(text)

    for chunk in chunks:
        print(f"  Start: {chunk.start_index}, End: {chunk.end_index}")
        print(f"  Method: {chunk.metadata.get('method')}")
        print(f"  Preview: {chunk.text[:80]}...")
    ```
  </Step>
  <Step title="或切分文档对象">
    ```python
    # split_documents() accepts any object with a .text attribute,
    # or a plain string: no specific document class required.
    class Doc:
        def __init__(self, text, metadata=None):
            self.text = text
            self.metadata = metadata or {}

    doc = Doc(text="Annual report content...", metadata={"source": "annual_report.pdf"})

    splitter = TextSplitter(method="structural")
    chunks   = splitter.split_documents([doc])

    for chunk in chunks:
        print(f"  {chunk.text[:80]}...")
    ```
  </Step>
  <Step title="批量切分文档列表">
    ```python
    # split_documents() returns a flat List[Chunk] across all inputs
    all_chunks = splitter.split_documents(docs)

    for chunk in all_chunks:
        print(chunk.text[:80])
    ```
  </Step>
</Steps>

## 切分方法

| 方法 | 切分方式 | 适用场景 |
| :------ | :------------- | :-------- |
| `recursive` | 段落 → 句子 → 词语（级联回退） | 通用默认选择 |
| `semantic_transformer` | 嵌入句子，在余弦相似度下降处切分 | RAG：主题连贯性重要时 |
| `entity_aware` | 调整边界，使实体跨度绝不被切断 | NER 流水线 |
| `relation_aware` | 将主谓宾三元组保持在同一文本块内 | KG 构建 |
| `sentence` | 句子边界检测（正则、NLTK、spaCy） | 短文档、问答 |
| `paragraph` | 按段落边界切分 | 长篇文章、报告 |
| `token` | 经 tiktoken 或 transformers 统计 Token；硬性截断 | LLM 上下文窗口准备 |
| `word` | 按词数统计并带重叠 | 简单的近似 Token 切分 |
| `character` | 固定字符数并带重叠；最快，无需 NLP | 简单批量任务 |
| `sliding_window` | 按步长前进的固定大小窗口；重叠可配置 | 稠密检索（ColBERT、DPR） |
| `structural` | 标题/段落结构检测 | 具有显式标题层级的文本 |
| `embedding_semantic` | 基于嵌入相似度的边界（`semantic_transformer` 的别名） | 基于嵌入连贯性的 RAG |
| `hierarchical` | 章节 → 段落 → 句子的多级分块 | 多粒度检索 |

## 选择策略

选定方法之前，先过一遍这棵决策树：

- **在构建 KG？** → 用 `relation_aware`（保持三元组完整），纯 NER 场景则用 `entity_aware`
- **最看重检索质量的 RAG 系统？** → `semantic_transformer`
- **双编码器检索（ColBERT、DPR）需要稠密重叠？** → `sliding_window`
- **为固定窗口的 LLM 准备提示词？** → `token`
- **带标题的结构化文本？** → `structural`
- **需要段落级连贯性？** → `paragraph` 或 `sentence`
- **要快速切分且没有 NLP 开销？** → `recursive` 或 `character`

## TextSplitter 构造函数

```python
from semantica.split import TextSplitter

splitter = TextSplitter(
    method="semantic_transformer",   # chunking strategy: see Splitting Methods table
    chunk_size=1000,                 # target size in characters
    chunk_overlap=200,               # character overlap between adjacent chunks
    similarity_threshold=0.7,        # cosine similarity cutoff (semantic_transformer only)
    model="all-MiniLM-L6-v2",        # sentence-transformers model name (semantic_transformer only)
    ner_method="ml",                 # NER method (entity_aware only)
    relation_method="ml",            # relation extraction method (relation_aware only)
)
```

| 参数 | 类型 | 默认值 | 说明 |
| :--------- | :---- | :------- | :----------- |
| `method` | `str \| list[str]` | `"recursive"` | 分块策略，或作为回退链的方法列表 |
| `chunk_size` | `int` | `1000` | 以**字符**为单位的目标大小（而非 Token：如果你以前按 Token 设定大小，请乘以约 4 来逼近相同的边界） |
| `chunk_overlap` | `int` | `200` | 相邻文本块之间的字符重叠 |
| `similarity_threshold` | `float` | `0.7` | `semantic_transformer` 的余弦相似度阈值：越低切分越多 |
| `model` | `str` | `"all-MiniLM-L6-v2"` | `semantic_transformer` 使用的 sentence-transformers 模型名 |
| `ner_method` | `str` | `"ml"` | `entity_aware` 的 NER 方法：`"pattern"` \| `"regex"` \| `"ml"` \| `"huggingface"` \| `"llm"` |
| `relation_method` | `str` | `"ml"` | `relation_aware` 的关系抽取方法：`"ml"` \| `"llm"` \| `"huggingface"` |
| `tokenizer` | `str` | `"gpt-4"` | `token` 方法使用的 tiktoken 模型名：无法识别的名称会回退到 `cl100k_base` |

<Warning>
  **`chunk_overlap` 过小。** 没有重叠时，跨越文本块边界的事实会在两个文本块中都不可见。相对于 `chunk_size` 的 10%–20% 重叠是安全下限：`chunk_size=1000` 时，请设置 `chunk_overlap=100` 到 `200`。
</Warning>

## 切分方法详解

<Tabs>
  <Tab title="Recursive（默认）">
    先尝试按段落断开，再尝试句子边界，最后是词语边界：只有当文本块超过 `chunk_size` 时才逐级回退：

    ```python
    splitter = TextSplitter(method="recursive", chunk_size=1000, chunk_overlap=200)
    chunks   = splitter.split(text)
    ```

    **关键行为：**
    - 尽可能保留段落与句子结构
    - 优雅回退：生成的文本块绝不会超过 `chunk_size`
    - 重叠保证文本块边界之间的上下文连续性
    - 不确定该用哪种方法时，它是很好的起点
  </Tab>
  <Tab title="Semantic（语义）">
    使用 sentence-transformers 模型嵌入每个句子，只要相邻句子之间的余弦相似度低于 `similarity_threshold` 就进行切分。每个文本块只覆盖一个连贯主题：

    ```python
    from semantica.split import TextSplitter

    splitter = TextSplitter(
        method="semantic_transformer",
        model="all-MiniLM-L6-v2",      # any sentence-transformers model name
        similarity_threshold=0.7,       # 0.6 = more splits, 0.8 = fewer splits
        chunk_size=800,
        chunk_overlap=0,                # not needed: chunks are already coherent
    )
    chunks = splitter.split(text)
    ```

    **关键行为：**
    - 需要安装 `sentence-transformers` 包：默认使用 `all-MiniLM-L6-v2`，可通过 `model=` 配置
    - 生成长度不一的文本块：有的主题短，有的主题长
    - 未安装 `sentence-transformers` 时回退为按句子切分
    - 因需计算嵌入而比 `recursive` 慢；重复切分时请缓存嵌入

    <Tip>
      **语义切分需要足够的句子。** `semantic_transformer` 需要多个句子才能检测主题切换。对于短于约 300 词的文档，它的表现与 `sentence` 切分一样：请改用 `recursive`。
    </Tip>
  </Tab>
  <Tab title="Entity-Aware（实体感知）">
    内部运行 NER，然后调整文本块边界，确保任何实体提及都不会被切到两个文本块中：

    ```python
    from semantica.split import TextSplitter
    import os

    # ner_method is passed through to the internal NERExtractor.
    # Use "llm" for highest accuracy, "ml" (default) for speed.
    splitter = TextSplitter(
        method="entity_aware",
        chunk_size=512,
        chunk_overlap=50,
        ner_method="ml",   # "pattern" | "regex" | "ml" | "huggingface" | "llm"
    )
    chunks = splitter.split(text)

    for chunk in chunks:
        print(f"  entities in chunk: {chunk.metadata.get('entity_count', 0)}")
        print(f"  preview: {chunk.text[:80]}...")
    ```

    **关键行为：**
    - NER 在内部运行：实体抽取由切分器自动完成
    - 每个文本块的实体对象可在 `chunk.metadata["entities"]` 中获取
    - 文本块大小与 `chunk_size` 略有出入：边界调整幅度不超过一个句子
    - 支持所有实体类型：PERSON、ORGANIZATION、LOCATION、DATE 以及自定义类型
  </Tab>
  <Tab title="Relation-Aware（关系感知）">
    将主谓宾三元组保持在同一文本块内：这对 KG 流水线至关重要：

    ```python
    from semantica.split import TextSplitter

    # relation_method is passed through to the internal RelationExtractor.
    # Use "llm" for highest accuracy, "ml" (default) for speed.
    splitter = TextSplitter(
        method="relation_aware",
        chunk_size=512,
        relation_method="ml",   # "ml" | "llm" | "huggingface"
    )
    chunks = splitter.split(text)

    for chunk in chunks:
        print(f"  relations in chunk: {chunk.metadata.get('relation_count', 0)}")
        for rel in chunk.metadata.get("relationships", []):
            print(f"  {rel}")
    ```

    **关键行为：**
    - 关系抽取在内部运行：无需预先计算好的实体或三元组
    - 每个文本块的关系对象可在 `chunk.metadata["relationships"]` 中获取
    - 隐含实体感知行为：三元组中的两个实体同样保持完整
    - 最适合作为 `Parse → Split → Extract → Build KG` 流水线中的切分步骤
  </Tab>
  <Tab title="Structural（结构）">
    基于对标题与段落边界的结构分析来切分文本。每个标题或段落组都会成为文本块边界：

    ```python
    from semantica.split import TextSplitter

    splitter = TextSplitter(method="structural")
    chunks   = splitter.split(text)

    for chunk in chunks:
        print(f"  {chunk.text[:80]}...")
        print(f"  start: {chunk.start_index}, end: {chunk.end_index}")
    ```

    **关键行为：**
    - 直接处理纯文本：不要求结构化的文档格式
    - 尊重标题层级（以 `#` 开头的行或全大写标题）与段落分隔  
    - 使用 `max_chunk_size=` 参数而非标准的 `chunk_size=` 来控制最大尺寸
    - `StructuralChunker` 不可用时回退到 `recursive`
  </Tab>
</Tabs>

## Chunk Schema

<AccordionGroup>
  <Accordion title="Chunk 数据类">

```python
@dataclass
class Chunk:
    text:        str                    # the chunk's text content
    start_index: int                    # character offset of start in source text
    end_index:   int                    # character offset of end in source text
    metadata:    Dict[str, Any]         # method-specific fields: see table below
    id:          Optional[str] = None   # optional chunk identifier
```

  </Accordion>
  <Accordion title="Chunk 元数据字段">

元数据键因方法而异。下面只列出实现中实际会设置的键。

| 字段 | 类型 | 设置者 | 说明 |
| :----- | :---- | :------ | :----------- |
| `method` | `str` | 所有方法 | 产生该文本块的切分方法 |
| `chunk_size` | `int` | 大多数方法 | 该文本块的字符长度 |
| `sentence_count` | `int` | `sentence`、`semantic_transformer`、spaCy 路径 | 该文本块中的句子数 |
| `paragraph_count` | `int` | `paragraph` | 该文本块中的段落数 |
| `word_count` | `int` | `word` | 该文本块中的词数 |
| `token_count` | `int` | `token`；spaCy 可用时的 `sentence`/`semantic_transformer` | Token 数：不一定存在 |
| `entity_count` | `int` | `entity_aware` | 边界落在该文本块内的实体数量 |
| `entities` | `list` | `entity_aware` | 边界落在该文本块内的实体对象 |
| `relation_count` | `int` | `relation_aware` | 该文本块中的关系三元组数量 |
| `relationships` | `list` | `relation_aware` | 该文本块中的关系对象 |
| `element_count` | `int` | `structural` | 归入该文本块的结构元素数量 |
| `element_types` | `list[str]` | `structural` | 元素类型：`"heading"`、`"paragraph"`、`"list"` 等 |

  </Accordion>
</AccordionGroup>

## Tokenizer 选项

`token` 方法接受一个 `tokenizer=` 关键字参数，它会传给 `tiktoken.encoding_for_model()`。该值应为 tiktoken 模型名。无法识别的名称会自动回退到 `cl100k_base`。

| 取值 | 使用的编码 |
| :----- | :------------- |
| `"gpt-4"`（默认） | `cl100k_base` |
| `"gpt-3.5-turbo"` | `cl100k_base` |
| `"text-embedding-ada-002"` | `cl100k_base` |
| 任何无法识别的字符串 | 回退到 `cl100k_base` |

如果未安装 `tiktoken`，`token` 方法会回退为按空白分隔的词进行切分。

<Warning>
  **Tokenizer 用错。** `token` 方法会把 `tokenizer=` 的值传给 `tiktoken.encoding_for_model()`。如果 tiktoken 无法识别该模型名，它会静默回退到 `cl100k_base`。请传入有效的 tiktoken 模型名（例如 `"gpt-4"`、`"gpt-3.5-turbo"`），以获得确定性的行为。
</Warning>

## 流水线集成

`TextSplitter` 既可以单独使用，也可以手动与其他 Semantica 模块组合。下面的示例展示了一种顺序模式：解析文件、切分文本，然后从每个文本块中抽取实体：

```python
from semantica.parse import DocumentParser
from semantica.split import TextSplitter
from semantica.semantic_extract import NERExtractor

# Parse
parser = DocumentParser()
parsed = parser.parse("data/report.pdf")   # returns a dict with "full_text" key

# Split
splitter = TextSplitter(method="semantic_transformer", chunk_size=512)
chunks   = splitter.split(parsed["full_text"])

# Extract from each chunk
ner = NERExtractor(method="ml")

for chunk in chunks:
    entities = ner.extract(chunk.text)
    print(f"  {len(entities)} entities in chunk starting at {chunk.start_index}")
```

完整的流水线编排 API 请参阅[Pipeline 参考](pipeline)。

- [解析](parse) —— 在分块之前先解析文档：产出章节与元数据。
- [嵌入](embeddings) —— 为文本块生成嵌入，用于向量搜索与语义分块。
- [语义抽取](semantic_extract) —— 从单个文本块中抽取实体与关系。
- [流水线](pipeline) —— 将切分集成为具名的流水线步骤。
