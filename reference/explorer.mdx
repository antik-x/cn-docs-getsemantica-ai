**`semantica.explorer`** 是一个**基于浏览器的仪表盘**，用于探索知识图谱（Knowledge Graph）、管理本体（Ontology）和执行可视化分析：

- 索引化搜索：118k 节点上耗时 0.004ms：无需全量扫描
- Ontology Hub：可视化编辑器、SHACL Studio、对齐编写与健康仪表盘
- 任意两个节点之间的双向路径查找
- WebSocket 进度流式传输，实时监控流水线
- 启动后无需编写代码：在浏览器中完成全部图探索


## 入门

安装，把你的图导出为 JSON，然后启动：

```bash
pip install "semantica[explorer]"
```

```python
# 1. Export your graph to a JSON file
import json
from semantica.context import ContextGraph

graph = ContextGraph()
graph.add_node("Python",  "language",  properties={"paradigm": "multi-paradigm"})
graph.add_node("FastAPI", "framework", properties={"language": "Python"})
graph.add_edge("Python", "FastAPI", "enables")
graph.save_to_file("my_graph.json")
```

```bash
# 2. Launch the Explorer
semantica-explorer --graph my_graph.json
# → Loading graph...
# → Graph loaded: 2 nodes, 1 edges
# → Semantica Explorer · http://127.0.0.1:8000
#     API docs  http://127.0.0.1:8000/docs
#     Health    http://127.0.0.1:8000/api/health
```

浏览器会自动打开 `http://127.0.0.1:8000`。交互式 API 文档位于 `/docs`。

<Tip>
  `semantica.explorer` 是一个**服务器进程**，不是可导入的 Python 库。请使用 CLI 或 `python -m semantica.explorer` 启动。`app.py` 模块暴露了一个模块级 `app` 实例，可配合 uvicorn 或 Docker 使用。
</Tip>

## CLI 参考

`semantica-explorer` 命令恰好接受四个标志：

| 标志 | 简写 | 默认值 | 描述 |
| :---- | :----- | :------- | :----------- |
| `--graph` | `-g` | *(**必需**)* | 要加载的 ContextGraph JSON 文件路径 |
| `--port` | `-p` | `8000` | 服务器绑定的端口 |
| `--host` |: | `127.0.0.1` | 服务器绑定的主机：使用 `0.0.0.0` 暴露到网络 |
| `--no-browser` |: | 关闭 | 跳过自动打开浏览器标签页 |

<Note>
  CLI 中没有用于身份验证、CORS 或日志级别的标志。CORS 允许的来源通过 `EXPLORER_CORS_ORIGINS` 环境变量配置（逗号分隔，默认值：`http://localhost:5173,http://127.0.0.1:5173`）。
</Note>

<Tip>
  **CORS 来源通过环境变量配置。** 启动之前，把 `EXPLORER_CORS_ORIGINS` 设置为以逗号分隔的允许来源列表（例如 `EXPLORER_CORS_ORIGINS="http://myapp.example.com"`）。
</Tip>

```bash
# Full example
EXPLORER_CORS_ORIGINS="http://myapp.example.com" \
  semantica-explorer --graph my_graph.json --host 0.0.0.0 --port 8080 --no-browser
```

## 你将获得

- **Graph Explorer** —— 交互式节点/边搜索、路径查找与邻域扩展。在 118k 节点的图上索引搜索仅需 0.004ms。
- **Ontology Hub** —— SKOS 词表管理、SHACL 形状生成与校验、本体对齐、健康仪表盘与版本管理。
- **Analytics** —— 度中心性、社区检测、连通性分析、图校验与距离矩阵。
- **REST API** —— 所有功能都以 REST API 的形式提供：完整文档见 `/docs`。
- **WebSocket 更新** —— 通过 WebSocket 在 `/ws/graph-updates` 上流式推送实时图变更事件。
- **CLI 启动器** —— `semantica-explorer --graph my_graph.json`，即刻本地启动。

## 功能特性

<Tabs>
  <Tab title="Graph Explorer">
    浏览知识图谱的核心仪表盘：

    - **索引搜索**：向 `/api/graph/search` POST 一个查询；118k 节点的图上 0.004ms
    - **路径查找**：通过 `GET /api/graph/path?source=&target=` 在任意两个节点之间执行 BFS 或 Dijkstra
    - **邻域扩展**：`GET /api/graph/node/{id}/neighbors?depth=2`
    - **按实体类型过滤**：`GET /api/graph/nodes?type=Person`
    - **语义邻域**：`GET /api/graph/semantic-neighborhood?node_id=&top_k=20`
    - **距离矩阵**：`POST /api/graph/distance-matrix`

    <Warning>
      **保存为 JSON 之前先过滤大图。** CLI 会把整个 JSON 文件加载进内存。对于超过 10k 节点的图，请先过滤出相关子图再导出：力导向布局在超大图上会变得不可用。
    </Warning>
  </Tab>
  <Tab title="Ontology Hub">
    在浏览器中进行本体生命周期管理：

    - **注册表**：`GET /api/ontology/registry`：列出已加载的本体
    - **SKOS 词表**：`GET /api/ontology/skos/schemes`、`GET /api/ontology/skos/concept/{uri}`
    - **SHACL**：`POST /api/ontology/shacl/generate`、`POST /api/ontology/shacl/validate`
    - **对齐**：`GET/POST /api/ontology/alignments`、`POST /api/ontology/suggest-alignments`
    - **提案与版本管理**：`POST /api/ontology/propose`、`GET /api/ontology/versions/{uri}`
    - **健康状态**：`GET /api/ontology/health`
  </Tab>
  <Tab title="Analytics">
    针对已加载图谱运行的图指标：

    - **组合指标**：`GET /api/analytics?metrics=centrality,community,connectivity`
    - **图校验**：`GET /api/analytics/validation`
    - **富化：链接预测**：`POST /api/enrich/links`
    - **富化：去重**：`POST /api/enrich/dedup`
    - **富化：实体抽取**：`POST /api/enrich/extract`
    - **时序**：`GET /api/temporal/snapshot`、`GET /api/temporal/diff`、`GET /api/temporal/bounds`

    <Tip>
      **用 `/api/analytics/validation` 检查图质量。** 校验器会检测孤立节点、缺失类型和其他结构问题，在你把图暴露给下游流水线之前就发现问题。
    </Tip>
  </Tab>
  <Tab title="决策与溯源">
    决策追踪与溯源（Provenance）查询：

    - **决策**：`GET /api/decisions`、`GET /api/decisions/{id}`、`GET /api/decisions/{id}/chain`
    - **先例**：`GET /api/decisions/{id}/precedents`
    - **因果距离**：`GET /api/decisions/causal-distance?source=&target=`
    - **合规**：`GET /api/decisions/{id}/compliance`
    - **溯源**：`GET /api/provenance?node_id=`、`GET /api/provenance/report?node_id=`
    - **标注**：`GET/POST /api/annotations`、`DELETE /api/annotations/{id}`

    <Tip>
      **自动化用 REST API，探索用 Explorer UI。** Explorer 的 REST 端点是稳定的编程接口：把它们接入脚本，即可自动化批量标注、SPARQL 查询或导出。
    </Tip>
  </Tab>
</Tabs>

## WebSocket 图更新

实时图变更事件通过 WebSocket 在 `ws://localhost:8000/ws/graph-updates` 上流式推送：

```python
import asyncio
import json
import websockets

async def watch_updates():
    async with websockets.connect("ws://localhost:8000/ws/graph-updates") as ws:
        # Server sends an ack on connect
        ack = json.loads(await ws.recv())
        print("Connected:", ack)

        # Send a ping to verify the connection is alive
        await ws.send("ping")

        async for message in ws:
            event = json.loads(message)
            print("[{}] {}".format(event["event"], event.get("data")))

asyncio.run(watch_updates())
```

WebSocket 消息 Schema：

```json
{
  "event":     "graph_mutation",
  "data": {
    "event_type":  "ADD_NODE",
    "entity_id":   "node_123",
    "payload":     {}
  },
  "timestamp": "2024-01-15T10:30:00+00:00"
}
```

WebSocket 上广播的事件类型包括：`connection_ack`、`pong` 和 `graph_mutation`（在通过导入或富化添加/更新/删除节点或边时触发）。发送文本 `"ping"` 即可收到 `pong` 响应。

<Warning>
  **服务器重启后会丢失会话状态。** 没有自动保存。关闭之前，请用请求体 `{"format": "json"}` 调用 `POST /api/export` 下载当前状态。
</Warning>

## 性能

| 场景 | 延迟 |
| :-------- | :------- |
| 节点搜索（118k 节点，索引化） | 0.004ms |
| 邻域扩展（深度 2） | < 5ms |
| BFS 路径（118k 节点） | < 50ms |
| SPARQL SELECT（简单模式） | < 20ms |
| 距离矩阵（50 个节点，语义） | ~2s（带嵌入缓存） |

节点搜索索引在启动时构建。对于超过 500k 节点的图，请在连接之前预留额外的启动时间。

距离矩阵每次请求最多 50 个节点对。语义距离要求节点的属性中存储了嵌入。

## 故障排查

**浏览器标签页没有打开**
服务器启动 1.5 秒后才会打开浏览器。如果自动打开失败，请使用 `--no-browser` 并手动打开 `http://127.0.0.1:8000`。

**`Error: graph file not found`**
`--graph` 路径必须是一个已存在的文件。启动之前，请检查路径并确认文件存在。

**`Error: uvicorn is required`**
安装 explorer 附加依赖：`pip install "semantica[explorer]"`。

**API 调用出现 `Connection refused`**
服务器默认只绑定 `127.0.0.1`。要从其他机器或容器访问 Explorer，请用 `--host 0.0.0.0` 启动。

**导入后图为空**
导入端点（`/api/import`）只解析 `.json` 和 `.csv` 文件。其他格式返回 HTTP 422。JSON 文件必须包含顶层的 `entities`/`nodes` 数组或 `relationships`/`edges` 数组。

**`/api/graph/path` 报 `PathFinder not available` 错误**
路径查找需要 `semantica[kg]` 附加依赖。请用 `pip install "semantica[all]"` 安装。

**语义邻域返回 503**
语义邻域要求节点属性中存储了节点嵌入（键为 `embedding`、`vector` 或 `node2vec_embedding`）。没有嵌入的图会返回 503。

**重启后丢失会话状态**
会话状态仅保存在内存中。关闭之前，请使用 `POST /api/export` 保存 JSON 快照。

- [Context](context)——构建并保存 Explorer 所加载的 ContextGraph。
- [Ontology](ontology)——以编程方式进行本体管理与 SHACL 生成。
- [可视化](visualization)——无需 Explorer 服务器的编程式图渲染。
- [Export](export)——无需启动服务器即可导出为 RDF、Parquet 和其他格式。
