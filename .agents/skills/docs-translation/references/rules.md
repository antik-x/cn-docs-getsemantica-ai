# Semantica 文档翻译规则（约束性摘要）

源：https://docs.getsemantica.ai/ （源码：github.com/semantica-agi/semantica 仓库 `docs/` 目录，MIT）
目标：`/Users/admins/web/ai/cn-docs-getsemantica-ai/cn-docs-getsemantica-ai/` 下的 Mintlify 站点，URL/slug 与原站一一对应，输出为 `.mdx`。

## A. 忠实（信）

1. 逐语义单元翻译：先读懂整段，再以中文技术作者的口吻重述。**不增删任何信息**——不加解释、不加总结、不删例子、不合并段落。
2. 语气与原文一致：第二人称（你/您的选择统一为「你」）、主动语态、直接陈述。原文的强调（粗体/斜体）在译文中落在语义对应的位置。
3. 原文的内容承诺（数字、版本号、限制、默认值）必须原样保留。

## B. 结构锁定（达的骨架）

每篇译文与源文必须满足：

1. **标题**：层级与数量一一对应（H1→H1，H2→H2，H3→H3，顺序不变）。
2. **代码围栏**：数量相同，**围栏内内容逐字节一致**（含注释、含 `<Exploits>` 之类伪标签、含 JSON 键值）。语言标注（```python 等）与围栏标题（可选的文件名行）原样保留。
3. **行内代码** `...`：内容逐字节保留，位置与源文语义对应。
4. **列表**：有序/无序种类不变，项数不变，嵌套层级不变。
5. **表格**：行数、列数不变；表头译中文，单元格内代码身份保留。
6. **链接**：URL、相对路径、锚点、查询串逐字节保留（如 `../reference/kg`、`/guides/graphrag#usage`）；**链接文字**翻译。
7. **图片/媒体**：`src`、`style` 等属性逐字节保留；`alt` 文字翻译。
8. **JSX 组件**（本站大量使用 `<Tabs>/<Tab>/<Steps>/<Step>/<Accordion>/<AccordionGroup>/<Tip>/<Warning>/<Note>/<Info>/<Check>/<CodeGroup>`）：
   - 标签种类、嵌套结构、数量不变；
   - **只翻译**：标签之间的人类语言文本，以及展示型属性值（`title="..."`、`label="..."`、`description="..."`、`alt="..."`）；
   - **不翻译**：`id`、`icon`、`href`、`src`、`style` 等功能性属性值；
   - 自闭合写法、属性顺序、缩进保持原样。
9. **frontmatter**：`title` 与 `description` 译中文（title 简洁，与导航一致；description 忠实完整）；`icon` 原样保留；不增删键。
10. **转义**：源文中 `\{`、`` \` ``、`&lt;` 等转义写法原样保留；译文中不得引入裸 `{ } < >`（MDX 会编译失败）。
11. **水平线、空行分段**：与源文一致。

## C. 术语纪律（雅的边界）

- 术语表：`/Users/admins/web/ai/cn-docs-getsemantica-ai/translation/terminology.md`，**必读、双向约束**。
- 核心概念正文首现用「中文（English）」；标题里不加对照。
- 未收录且无可引用中文先例的术语：保留英文，并在任务报告「待定术语」中列出。
- 同一篇内同一术语译法必须唯一。

## D. 中文排版（雅）

1. 全角标点：，。；：？！（）；破折号——；省略号……。引用可用「」。
2. 中西文之间加一个空格（含中文与数字之间，如「3 个模块」「使用 pip 安装」）；英文单词内部、数字串内部不加空格。
3. 全角括号内若是纯英文/代码，用半角括号且外侧不加空格：如「嵌入（Embedding）」用全角；`（见 ContextGraph）`这类纯代码内容可用半角。
4. 标题不使用句末标点；列表项为完整句子时用句号，短语时不加。
5. 金额/单位/百分号写法：50%、3 GB、v1.2。

## E. 流程

1. 翻译前先读术语表与本规则；逐文件处理：读源文 → 译文写入目标路径（`.mdx`）→ 自检。
2. **自检**（每篇必做）：数标题层级与数量、数代码围栏并抽样比对围栏内容、数列表项、数表格行列、核对链接/图片/JSX 标签数量；通读中文成稿一遍，改掉翻译腔（「被」「进行」「的的不休」等）。
3. 任务报告格式：每文件一行 `OK <路径>`，最后列出「待定术语」与任何不确定之处。不贴译文全文。
