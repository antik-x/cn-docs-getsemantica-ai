安装基础包后，你的 `PATH` 中会注册五个可执行文件，各有各的用途。本页说明它们分别是什么、如何确认它们可用，以及在各种情况下该选用哪一个。


## 已安装的命令

```bash
pip install semantica
```

安装完成后，以下命令即可使用：

| 命令 | 入口点 | 作用 |
| :------- | :----------- | :------------ |
| `semantica` | `semantica.cli:main` | 通用 CLI，用于流水线运行、抽取与图谱操作 |
| `semantica-server` | `semantica.server:main` | 绑定到 `0.0.0.0:8000` 的 FastAPI/uvicorn REST API 服务器 |
| `semantica-worker` | `semantica.worker:main` | Semantica 部署中的后台工作进程入口 |
| `semantica-explorer` | `semantica.explorer:main` | 用于知识图谱探索的交互式浏览器仪表盘 |
| `semantica-mcp` | `semantica.mcp_server:main` | 面向 Claude Desktop、Cursor、Windsurf 及其他 MCP 客户端的 MCP 服务器（stdio） |

<Note>
  `semantica-explorer` 需要 `pip install semantica[explorer]`。如果不安装该可选依赖就运行它，它会立即打印错误并退出。完整流程见[知识探索器配置](explorer-setup)。
</Note>


## 验证安装

确认每条命令都可访问并能打印用法：

```bash
semantica --help
semantica-server --help
semantica-worker --help
semantica-explorer --help
semantica-mcp --help
```

确认软件包版本：

```bash
python -c "import semantica; print(semantica.__version__)"
```


## 各命令的使用时机

- **semantica** —— 通用 CLI。用于从 shell 脚本或 CI 任务中执行一次性的流水线运行、实体抽取与图谱操作。
- **semantica-server** —— 启动 REST API 服务器，绑定到 `0.0.0.0:8000`。当其他服务或应用需要通过 HTTP 以编程方式访问 Semantica 时，使用它。
- **semantica-worker** —— 后台任务处理器。当你需要在请求周期之外执行异步流水线时，让它与 `semantica-server` 一同运行。先启动服务器，再启动一个或多个指向同一后端的工作进程。
- **semantica-explorer** —— 启动浏览器仪表盘。需要 `pip install semantica[explorer]`。用于以交互方式探索已保存的知识图谱。参见[知识探索器配置](explorer-setup)。
- **semantica-mcp** —— 通过 stdio 运行模型上下文协议（MCP）服务器。在 MCP 客户端的设置文件中配置它，即可向 Claude Desktop、Cursor、Windsurf 或任何支持 MCP 的客户端暴露全部 12 个工具与 3 个资源。参见[MCP Server](reference/mcp_server)。


## 用法示例

<Tabs>
  <Tab title="REST 服务器">
    ```bash
    # Starts FastAPI + uvicorn on 0.0.0.0:8000
    semantica-server
    ```

    启动后，可用以下方式检查：

    ```bash
    curl http://localhost:8000/health
    # {"status": "ok"}

    curl http://localhost:8000/api/info
    # {"name": "Semantica API", "version": "...", "status": "active"}
    ```

    交互式 API 文档位于 `http://localhost:8000/docs`。
  </Tab>
  <Tab title="工作进程">
    ```bash
    semantica-worker
    ```

    工作进程在收到 `SIGINT`（Ctrl-C）或 `SIGTERM` 时会干净退出。
  </Tab>
  <Tab title="MCP 客户端配置">
    添加到你的 MCP 客户端设置文件中：

    ```json
    {
      "mcpServers": {
        "semantica": {
          "command": "semantica-mcp"
        }
      }
    }
    ```

    如果命令不在 `PATH` 中，可改用 Python 模块形式：

    ```json
    {
      "mcpServers": {
        "semantica": {
          "command": "python",
          "args": ["-m", "semantica.mcp_server"]
        }
      }
    }
    ```

    在配置客户端之前，先直接测试一下：

    ```bash
    echo '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"test","version":"1.0"}}}' | semantica-mcp
    ```

    你应该会收到一条 JSON-RPC 响应。完整的工具与资源列表见[MCP Server](reference/mcp_server)。
  </Tab>
  <Tab title="知识探索器">
    ```bash
    pip install semantica[explorer]
    semantica-explorer --graph my_graph.json
    ```

    包括如何构建并保存图谱文件在内的完整流程，见[知识探索器配置](explorer-setup)。
  </Tab>
  <Tab title="Python 模块形式">
    每条命令也可以作为 Python 模块运行——当脚本目录不在 `PATH` 中时很有用：

    ```bash
    python -m semantica.mcp_server
    python -m semantica.explorer --graph my_graph.json
    ```
  </Tab>
</Tabs>


## 环境变量

`semantica-mcp` 读取两个环境变量：

| 变量 | 默认值 | 说明 |
| :-------- | :------- | :----------- |
| `SEMANTICA_KG_PATH` | *(none)* | 启动时加载的已保存图谱文件路径 |
| `SEMANTICA_LOG_LEVEL` | `WARNING` | 日志详细程度：`DEBUG`、`INFO`、`WARNING` |

`semantica-server` 读取一个：

| 变量 | 默认值 | 说明 |
| :-------- | :------- | :----------- |
| `SEMANTICA_CORS_ORIGINS` | `http://localhost:5173,http://127.0.0.1:5173` | 允许的 CORS 来源列表（逗号分隔） |

这些命令不读取其他任何环境变量。


## 故障排除

<AccordionGroup>

<Accordion title="command not found" icon="terminal">

这些可执行文件位于当前 Python 环境的 `bin/`（Linux/Mac）或 `Scripts/`（Windows）目录中。如果找不到命令，很可能是该目录不在 `PATH` 中。

先激活你的虚拟环境：

```bash
source venv/bin/activate   # Linux / Mac
venv\Scripts\activate      # Windows
semantica --help
```

找到 pip 放置脚本的位置：

```bash
python -m site --user-scripts   # user-level install
pip show -f semantica           # shows all installed files
```

</Accordion>

<Accordion title="命令存在，但导入时崩溃" icon="triangle-exclamation">

```bash
pip install --upgrade semantica
python -c "import semantica; print(semantica.__version__)"
```

如果你有多个 Python 环境，请安装到 shell 实际解析到的那个环境中：

```bash
python -m pip install semantica
```

</Accordion>

<Accordion title="semantica-explorer：需要 uvicorn" icon="map">

基础安装不包含 Explorer 可选依赖：

```bash
pip install semantica[explorer]
```

</Accordion>

<Accordion title="semantica-mcp 在 MCP 客户端内静默失败" icon="plug">

MCP 服务器通过 stdio 通信。请先在 shell 中直接测试：

```bash
echo '{"jsonrpc":"2.0","id":1,"method":"ping","params":{}}' | semantica-mcp
```

收到 `{"jsonrpc":"2.0","id":1,"result":{}}` 这样的响应即说明服务器工作正常。如果毫无输出，请检查命令是否在 `PATH` 中，以及基础包是否已安装。

</Accordion>

<Accordion title="Windows：启动时出现 DLL 错误" icon="windows">

请安装 [Microsoft Visual C++ Redistributable](https://aka.ms/vs/17/release/vc_redist.x64.exe)。这是 Windows 的系统依赖，PyTorch 及相关包都需要它，并不是 Semantica 的 bug。

</Accordion>

</AccordionGroup>
