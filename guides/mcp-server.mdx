## 什么是 MCP？

MCP 即模型上下文协议（Model Context Protocol），是一项开放标准，允许外部 AI 助手（如 Claude Desktop、Cursor 或 Windsurf）安全地访问本地工具和数据源。

Semantica MCP 服务器将你的知识图谱（Knowledge Graph）暴露为 12 个可调用的工具。接入之后，任何兼容的 AI 客户端都能在对话过程中实时遍历图谱、记录决策、运行分析并导出结果——而你无需编写任何自定义工具封装。

<Info>
  Semantica MCP 服务器提供 12 个工具和 3 个只读资源。所有工具均接受并返回 JSON。除一个用于图谱持久化的可选环境变量外，无需任何配置。
</Info>

## 架构与通信

理解 MCP 的底层工作方式很重要。**Semantica MCP 服务器不是 REST API。**它不开放网络端口，没有 HTTP 端点，也不需要 API 密钥。

AI 客户端会在本地以子进程方式启动 `semantica-mcp`。AI 与 Semantica 之间的所有通信都通过标准输入输出（`stdio`）安全进行。由于服务器在你的用户账户下本地运行，它天然拥有你的本地文件权限。

## 为什么在 Semantica 中使用 MCP？

- **零代码集成**：无需编写任何胶水代码，即可将 Semantica 的图能力即时接入你喜爱的 AI IDE 或桌面聊天应用。
- **实时图谱更新**：与 AI 对话即可从文档中抽取实体，并看着它们即刻填充到你的实时知识图谱中。
- **可审计的 AI**：让 AI 做决策，并通过 Semantica 的决策智能工具自动将推理过程和因果链直接记录到图谱中。

## 何时使用 / 何时不用

- **适用场景**：你想使用第三方 AI 界面（如 Claude Desktop 或 Windsurf）在本地机器上操作、查询 Semantica 知识图谱并对其进行推理。
- **不适用场景**：你在构建自主运行的 Python 脚本或后端服务。如果你正在编写 Python 代码来构建智能体，请直接使用 `semantica.context.AgentContext`，而不是启动一个 MCP 服务器。MCP 服务器不支持通过 HTTP/SSE 进行远程托管。

## 典型工作流

连接你的 AI 客户端遵循以下标准步骤：

1. **安装**：在你的 Python 环境中安装 Semantica。
2. **配置客户端**：将 `semantica-mcp` 命令和图谱的绝对路径添加到 AI 客户端的 JSON 配置中。
3. **启动客户端**：启动 Claude Desktop 或 Windsurf，它们会自动拉起 MCP 服务器。
4. **工具调用**：用自然语言向 AI 下达提示词。AI 会自主串联这 12 个可用工具。
5. **图谱更新**：AI 直接修改你的本地图谱，添加实体、边和决策。

## 启动服务器

安装 Semantica，然后配置客户端以启动 MCP 服务器。服务器使用 `stdio` 传输方式运行。

```bash
pip install semantica
```

```bash
# Via the CLI entry-point (recommended)
semantica-mcp

# Or via the Python module directly
python -m semantica.mcp_server
```

默认情况下，服务器以 `WARNING` 级别记录日志，启动时不产生任何输出。设置 `SEMANTICA_LOG_LEVEL=INFO`（或 `DEBUG`）即可在 stderr 上看到启动消息。未设置 `SEMANTICA_KG_PATH` 时，服务器会初始化一个空的内存图谱——用于测试已足够。若要得到重启后依然存在的持久化图谱，请设置该路径：

```bash
SEMANTICA_KG_PATH=/data/threat_graph.json semantica-mcp
```

<Info>
  未设置 `SEMANTICA_KG_PATH` 时，服务器进程退出后图谱即被重置。任何需要数据在重启后保留的会话，都务必用绝对文件路径设置该变量。
</Info>

## 连接到 Claude Desktop

编辑 Claude Desktop 配置文件——macOS 上位于 `~/Library/Application Support/Claude/claude_desktop_config.json`，Windows 上位于 `%APPDATA%\Claude\claude_desktop_config.json`：

```json
{
  "mcpServers": {
    "semantica": {
      "command": "semantica-mcp",
      "env": {
        "SEMANTICA_KG_PATH": "/absolute/path/to/knowledge_graph.json",
        "SEMANTICA_LOG_LEVEL": "INFO"
      }
    }
  }
}
```

保存后重启 Claude Desktop。Semantica 工具会自动出现在工具面板中——Claude 现在可以在任何对话中调用它们。

如果 `semantica-mcp` 不在系统 PATH 中（例如安装在 virtualenv 里），请在 `"command"` 中使用完整的二进制文件绝对路径：`"/path/to/venv/bin/semantica-mcp"`。

## 连接到其他客户端

**Windsurf**——在 Settings → MCP Servers → Add Server 中添加，或编辑 `~/.windsurf/mcp_servers.json`：

```json
{
  "semantica": {
    "command": "semantica-mcp",
    "env": { "SEMANTICA_KG_PATH": "/absolute/path/to/knowledge_graph.json" }
  }
}
```

**VS Code（Cline / Roo Code / Continue）**——添加到项目根目录的 `.mcp.json`：

```json
{
  "servers": {
    "semantica": {
      "type": "stdio",
      "command": "semantica-mcp",
      "env": {
        "SEMANTICA_KG_PATH": "${workspaceFolder}/knowledge_graph.json",
        "SEMANTICA_LOG_LEVEL": "DEBUG"
      }
    }
  }
}
```

**Docker**：

```bash
docker run --rm -i \
  -e SEMANTICA_KG_PATH=/data/kg.json \
  -v /local/absolute/path:/data \
  ghcr.io/semantica-agi/semantica-mcp:latest
```

## 智能体能做什么：12 个工具

连接完成后，大语言模型（LLM）可以在对话中调用其中任何一个工具。智能体会自动串联它们——你无需编排调用顺序，只需描述你想要什么。

**实体与关系抽取**——`extract_entities` 从自由文本中抽取命名实体；`extract_relations` 抽取语义关系和 RDF 三元组。这两个工具无需任何预处理，就能把原始 OSINT 报告转化为结构化的图谱输入。

**知识图谱操作**——`add_entity` 添加节点，`add_relationship` 添加有向边。抽取完成后，智能体会调用它们把发现的内容持久化到实时图谱中。

**决策智能**——`record_decision` 将一条决策写成一个溯源节点，附带置信度得分、推理过程和决策者身份。`query_decisions` 按查询或类别检索过去的决策。`find_precedents` 通过语义相似度找出最相似的过往决策。`get_causal_chain` 沿上游或下游追踪决策的因果关系。

**推理**——`run_reasoning` 对一组事实应用前向链式 IF/THEN 规则，返回推导出的结论。

**分析与导出**——`get_graph_analytics` 计算 PageRank 中心性并执行社区检测。`get_graph_summary` 返回节点数、决策数和服务器状态。`export_graph` 将当前图谱序列化为 Turtle（`"turtle"` / `"ttl"`）、RDF/XML（`"xml"`）、N-Triples（`"nt"`）、JSON-LD（`"json-ld"`）或纯 JSON（`"json"`）。

## 通用示例：员工通讯录

在深入复杂的领域示例之前，先看一个简单易懂、人人都能明白的会话。一位 HR 经理在 Claude Desktop 中输入了这样一段提示词：

> "从这份关于 Alice 转岗到工程部门的会议记录中抽取实体，把它们加入图谱，并记录一条晋升决策。"

Claude 自动串联了四次工具调用：

```text
1. extract_entities(text="Alice is transferring to Engineering...")
   → { "entities": [{"label": "Alice", "type": "Employee"}, {"label": "Engineering", "type": "Department"}] }

2. add_entity(id="emp-alice", label="Alice", type="Employee")
   add_entity(id="dept-eng", label="Engineering", type="Department")

3. add_relationship(source="emp-alice", target="dept-eng", type="WORKS_IN")

4. record_decision(
       category="promotion",
       scenario="Alice transferring to Engineering",
       reasoning="Approved by Engineering Director",
       outcome="transfer_approved",
       confidence=1.0
   )
```
图谱随即更新了新的组织结构，以及一条完全可审计的决策轨迹。

## 观察一次真实的智能体会话

下面展示的是当一位网络安全分析师在 Claude Desktop 中输入提示词、且图谱处于实时状态时会发生什么。提示词是：

> "从这份 OSINT 报告中抽取实体和关系，把它们加入知识图谱，然后为 APT29 记录一条置信度为 0.88 的归因决策，并将完整图谱导出为 Turtle 格式。"

Claude 自动串联了六次工具调用：

```text
1. extract_entities(text="<report text>")
   → { "entities": [{"label": "APT29", "type": "ThreatActor"}, ...] }

2. extract_relations(text="<report text>")
   → { "relations": [{"source": "APT29", "type": "EXPLOITS", "target": "CVE-2024-3400"}] }

3. add_entity(id="apt29", label="APT29", type="ThreatActor", metadata={"alias": "NOBELIUM"})
   → { "status": "added", "id": "apt29" }
   (repeated for each extracted entity)

4. add_relationship(source="apt29", target="cve-2024-3400", type="EXPLOITS",
                    metadata={"confidence": 0.97})
   → { "status": "added" }
   (repeated for each extracted relation)

5. record_decision(
       category="threat_attribution",
       scenario="C2 beacon from 185.220.101.47, TTP T1566.001 observed",
       reasoning="IP overlaps APT29 infrastructure cluster; TTPs match NOBELIUM phishing playbook",
       outcome="attributed_to_apt29",
       confidence=0.88,
       decision_maker="analyst_zhang"
   )
   → { "decision_id": "dec_a3f2b1", "status": "recorded" }

6. export_graph(format="turtle")
   → { "format": "turtle", "data": "@prefix ... <apt29> a :ThreatActor ..." }
```

分析师用自然语言问了一个问题。六次结构化的工具调用就在实时图谱数据上完成了。结果是一张填充完毕的图谱、一条带有完整溯源的归因决策记录，以及一份随时可用于 SPARQL 端点的 Turtle 导出——所有这些都在一轮对话中完成。

## 三个只读资源

资源无需工具调用即可暴露图谱状态——客户端可以在任意时刻读取它们：

| URI | 描述 |
| :-- | :---------- |
| `semantica://graph/summary` | 节点数、决策数、服务器状态 |
| `semantica://decisions/list` | 最近记录的最多 50 条决策 |
| `semantica://schema/info` | 服务器版本、能力、可用工具列表 |

## 常见陷阱

- **把 MCP 当作 HTTP 服务器**：不要试图 `curl` MCP 服务器，也不要寻找端口号。它通过 `stdin/stdout` 通信，等待来自父级 AI 客户端的 JSON-RPC 消息。
- **为 `SEMANTICA_KG_PATH` 使用相对路径**：由于 AI 客户端以子进程方式拉起服务器，工作目录可能不可预测。务必使用绝对路径（如 `C:\Users\Name\graph.json` 或 `/Users/name/graph.json`），以免丢失数据。
- **虚拟环境 PATH 问题**：如果你把 Semantica 安装在 Python 虚拟环境中，Claude Desktop 不会自动在全局系统 PATH 上找到 `semantica-mcp`。你必须在 `"command"` 字段中提供二进制文件的绝对路径。
- **期待远程托管支持**：基于 stdio 的 MCP 服务器必须与 AI 客户端运行在同一台本地机器上，不支持通过网络远程执行。
- **混淆 MCP 集成与 `AgentContext`**：如果你正在编写自己的 Python 代码来编排 LLM，请不要使用 MCP 服务器，而应在代码中直接使用 `AgentContext` 类。

## 故障排除

**服务器未出现在 Claude Desktop 中**——编辑配置后，彻底退出并重新打开 Claude Desktop（仅关闭窗口是不够的）。确认二进制文件在 PATH 上：Unix 上用 `which semantica-mcp`，Windows 上用 `where semantica-mcp`。如果使用 virtualenv，请在 `"command"` 中使用二进制文件的绝对路径。设置 `SEMANTICA_LOG_LEVEL=DEBUG`，并检查 stderr 中的启动错误。

**图谱数据未在会话之间持久化**——将 `SEMANTICA_KG_PATH` 设置为绝对文件路径。否则图谱仅存在于内存中，每次服务器重启都会重置。

**工具调用返回空结果**——`get_graph_summary` 返回 `"node_count": 0` 说明图谱为空。可通过 `add_entity` 和 `add_relationship` 填充图谱，或先对文本运行 `extract_entities`，再对每个结果调用 `add_entity`。

**`SEMANTICA_KG_PATH` 出现权限错误**——服务器进程需要对该文件及其父目录的读写权限。如果在 Docker 中运行，请检查卷挂载和文件所有权。
