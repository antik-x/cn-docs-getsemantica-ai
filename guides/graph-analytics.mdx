`ContextGraph` 分析——中心性、社区检测、Node2Vec 嵌入（Embedding）、链接预测和结构相似度——回答的是你的图谱*意味着什么*，而不仅仅是它包含什么。用 `advanced_analytics=True` 一次性启用它们，即可用来为结构上最重要的节点排名、发现隐藏的运营集群，并在隐含连接被正式观测到之前将其标记出来。

## 什么是图分析？

图分析运用数学算法来发现知识图谱（Knowledge Graph）结构中的模式与性质。它超越了单纯的数据存储与检索，直接分析关系本身。

**图分析与图遍历的对比：**遍历沿着既有的边找到相连的节点。分析则审视整个图结构来发现模式——哪些节点最具影响力、哪些节点群构成社区、哪些连接缺失。

**图分析与推理的对比：**推理应用逻辑规则推导新事实。分析应用统计与拓扑算法来度量中心性、聚类和相似度等结构性质。

图分析帮助你理解数据中的*形态*和*重要性模式*，揭示从单个节点或边看不出来的洞见。

## 为什么使用图分析？

**发现有影响力的实体。**节点的重要性并不相同。分析能识别哪些实体在网络结构中处于最中心、连接最多或战略位置最关键的地方。

**社区发现。**分析通过研究连接密度模式，揭示隐藏的集群和运营团伙。聚在一起的实体往往共享单凭元数据看不出来的目的、来源或行为。

**关系发现。**链接预测识别尚未被明确观测到的可能连接，帮助调查者聚焦最可能缺失的关系。

**调查支持。**分析提供关于重要性和关联度的客观度量，帮助分析师排定优先级：先调查哪些实体、哪些关系值得深入审视。

**风险识别。**中心性度量能识别出哪些实体一旦被移除会最大程度扰乱网络——有助于理解单点故障、关键基础设施或高影响目标。

## 何时使用 / 何时不用

**图分析适用于：**
- 大型图谱（100 个以上节点），模式难以凭肉眼检视发现
- 依据结构重要性排定调查优先级
- 发现隐藏的社区和运营集群
- 理解网络韧性与脆弱点
- 通过链接预测识别缺失的关系

**图遍历可能就足够的情况：**
- 沿着特定实体之间的已知关系追踪
- 探索特定节点周围的邻域
- 在已知实体之间寻路

**推理可能就足够的情况：**
- 应用已知逻辑规则推导新事实
- 策略执行与基于规则的决策
- 关系遵循清晰逻辑模式的情形

**简单查询可能就足够的情况：**
- 模式一目了然的小型图谱
- 直接查找特定实体或关系
- 你明确知道自己要找什么的情况

**分析能提供价值的情况：**
- 你需要理解整体结构与模式
- 人工检视会遗漏重要的结构性质
- 你想发现意料之外的关系或社区
- 需要客观的重要性或相似度度量来指导决策

## 关键分析概念

**模块度（Modularity）**衡量图谱中的社区划分有多清晰。高模块度（>0.4）意味着检测出的社区内部连接多、外部连接少——表明存在真实的组织结构。

**Louvain 社区检测**找出彼此之间比与图中其余部分连接更紧密的节点群。它适用于发现运营集群、组织单元或功能群体。

**Node2Vec** 通过在图中模拟随机游走，为节点创建向量嵌入。在这些游走中出现在相似上下文里的节点，最终会得到相似的向量，即使它们并没有直接相连。

**中心性指标**从不同角度度量节点的重要性：
- 度（Degree）：有多少条直接连接
- 介数（Betweenness）：一个节点有多少次位于其他节点之间的最短路径上
- 特征向量（Eigenvector）：基于拥有重要邻居的重要性
- PageRank：在图的随机游走中的重要性

<Info>
  所有分析都要求在构造时传入 `advanced_analytics=True`。否则，本指南中的每个方法都会抛出 `RuntimeError: advanced_analytics not enabled`。该标志会懒加载初始化五个子组件：`CentralityCalculator`、`CommunityDetector`、`NodeEmbedder`、`LinkPredictor` 和 `SimilarityCalculator`。
</Info>

## 搭建用于分析的图谱

```python
from semantica.context import ContextGraph

graph = ContextGraph(
    advanced_analytics  = True,
    community_detection = True,
    node_embeddings     = True,
)
```

如果你正从存储加载一张已有图谱，请传入同样的标志——子组件会从加载的图谱状态初始化，而不是从一张全新的空图谱初始化。

## 一次调用的全景快照

在深入各项单独分析之前，先摸清整体情况。`analyze_graph_with_kg()` 会按顺序运行每一项分析，并返回一份统一的报告：

```python
report = graph.analyze_graph_with_kg()

print(f"Nodes:       {report['graph_metrics']['node_count']}")
print(f"Edges:       {report['graph_metrics']['edge_count']}")
print(f"Density:     {report['graph_metrics']['density']:.4f}")
print(f"Communities: {len(report['community_analysis'])}")
```

对于一张有 2,400 个节点、8,700 条边的图谱来说，0.003 的密度完全正常——知识图谱天然稀疏；大多数节点只与一个小邻域相连，而不是与所有东西相连。如果你看到密度高于 0.1，很可能存在连接过度的枢纽节点把所有东西拉到一起，这会扭曲中心性得分。

在每批摄取结束时运行它。运行结果为你提供一个基线，可与下一次运行对比——如果社区数在两个摄取周期之间从 12 降到 4，说明新数据中有什么东西桥接了原本分离的集群。这是一个值得在下一次分析师简报之前调查的信号。

完整的报告结构：

```text
report
├── "graph_metrics"         → node_count, edge_count, density
├── "centrality_analysis"   → all five measures + per-node rankings
├── "community_analysis"    → detected communities + modularity score
├── "connectivity_analysis" → connected components, diameter, avg path length
├── "node_embeddings"       → node_id → List[float] (Node2Vec vectors)
└── "timestamp"             → ISO datetime of this analysis run
```

## 找出核心节点——中心性分析

节点并非生而平等。中心性分析为每个节点给出五个不同的分数，每个分数度量一种不同的重要性。

关键直觉：一个节点的*度*可以很低（直接连接很少），但*介数*极高（一切都从它这里经过）。这就是一个**中介节点（broker）**——一旦移除它，图谱就会碎裂成互不相连的碎片。在威胁情报中，中介节点往往是基础设施节点：抗投诉托管（bulletproof hosting）服务商、共享的 C2 框架，或每场攻击活动都要经过的中转加载器。

### 为单个节点评分

当你怀疑某个特定实体很重要时，先从直接评分开始：

```python
scores = graph.get_node_centrality("APT29")

# degree      → 0.0420  (4.2% of nodes are direct neighbors)
# betweenness → 0.1837  (APT29 sits on 18% of all shortest paths)
# closeness   → 0.6123  (average 1.6 hops to any other node)
# eigenvector → 0.8941  (most of APT29's neighbors are themselves well-connected)
# pagerank    → 0.0089  (0.89% of random-walk probability mass lands here)

for measure, score in scores.items():
    print(f"{measure:12s}: {score:.4f}")
```

这里 0.18 的介数得分非常醒目——它意味着图中将近五分之一的信息流都要经过 APT29 这个中介。如果分析师想弄清「是什么把我们观测到的 TTP 与已知基础设施连接起来」，就必须经过 APT29。这不只是名气，而是结构性的权力。

### 全图批量排名

要一次对全部五个指标给所有节点排名：

```python
from semantica.kg import CentralityCalculator

calc       = CentralityCalculator()
graph_dict = graph.to_dict()

all_measures = calc.calculate_all_centrality(graph_dict)

# Pull top 5 by betweenness — these are your brokers
betweenness_rankings = all_measures["centrality_measures"]["betweenness"]["rankings"]
print("Top brokers (betweenness):")
for entry in betweenness_rankings[:5]:
    print(f"  [{entry['score']:.4f}]  {entry['node']}")
```

如果你只关心其中两个指标，可以传入子集，避免计算全部五个：

```python
focused = calc.calculate_all_centrality(
    graph_dict,
    centrality_types = ["degree", "pagerank"],
)
```

### 该信任哪个指标？

| 如果你想知道…… | 使用 |
| :--- | :--- |
| 谁拥有最多的直接连接？ | `degree` |
| 谁若被移除会最大程度扰乱网络？ | `betweenness` |
| 谁能最快到达网络其余部分？ | `closeness` |
| 谁因邻居有影响力而有影响力？ | `eigenvector` |
| 谁在图的随机遍历中很重要？ | `pagerank` |

在归因分析中，**特征向量**中心性往往能浮现出最有意义的节点——高特征向量意味着你与其他高特征向量节点相连，在威胁情报中，这与「公认重要」的实体彼此聚集的规律相符。

## 绘制威胁行为者聚类——社区检测

中心性告诉你单个节点的情况。社区检测告诉你*群体*的情况——哪些节点形成内部连接多于外部连接的紧密集群。

设想你的图谱中有二十个不同的威胁行为者节点。中心性可以单独为它们排名，却无法告诉你其中十二个实际上共享基础设施、工具模式和目标行业，从而构成单一的运营集群，而其余八个分裂成两个独立群体。社区检测能自动发现这一点。

```python
from semantica.kg import CommunityDetector

detector   = CommunityDetector()
result     = detector.detect_communities(graph.to_dict(), algorithm="louvain")

communities = result["communities"]       # List[List[str]] — node groups
assignments = result["node_assignments"]  # node_id → community index
modularity  = result["modularity"]        # 0.0–1.0 — partition quality

print(f"Found {len(communities)} communities  (modularity: {modularity:.3f})")

for i, members in enumerate(communities):
    print(f"\n  Community {i} — {len(members)} members")
    print(f"  Sample: {', '.join(members[:4])}")
```

**高于 0.4 的模块度**通常被认为是有意义的——发现的社区并非随机产物。如果你的图谱返回 0.71，这是一个强烈信号，表明聚类是真实存在的：你的威胁行为者确实形成了运营集群，而不只是随机关联。

当你看到一个社区混入了你以为互不相关的威胁行为者时，这就是一个值得调查的假设。`COZY BEAR`、`VENOMOUS BEAR` 和 `FANCY BEAR` 之所以出现在同一个社区，也许是因为它们共享 C2 基础设施——尽管传统上把它们归因于不同的 GRU 单位。

立即可视化：

```python
from semantica.visualization import KGVisualizer

viz = KGVisualizer()
viz.visualize_communities(
    graph       = graph,
    communities = communities,
    output      = "interactive",
    file_path   = "threat_clusters.html",
)
```

## 教图谱度量距离——Node2Vec 嵌入

中心性和社区检测是拓扑层面的——它们把边当作二值连接处理。Node2Vec 嵌入走得更深：它通过在图中模拟成千上万次随机游走，为每个节点生成一个稠密向量，从中学习哪些节点倾向于出现在相似的邻域中。

实际效果是：扮演相似*结构角色*的节点最终会落在嵌入空间中彼此附近的位置——即使它们之间没有直接的边。两个都处在威胁行为者与受害基础设施之间的 C2 域名，会得到相似的嵌入，哪怕它们位于图谱中完全不同的部分。

```python
from semantica.kg import NodeEmbedder
import numpy as np

embedder   = NodeEmbedder()     # requires: pip install semantica[embeddings]
embeddings = embedder.compute_embeddings(
    graph_store        = graph,   # ContextGraph instance — not a dict
    node_labels        = None,    # None = embed all node types
    relationship_types = None,    # None = traverse all edge types
)
# Returns: Dict[str, List[float]] — node_id → embedding vector

for node_id, vec in list(embeddings.items())[:3]:
    print(f"{node_id}: dim={len(vec)}, norm={np.linalg.norm(vec):.4f}")
```

这些向量在 Semantica 中是一等公民——它们以 `node2vec_embedding` 的形式存储在 `Decision` 节点上，并被 `find_precedents_by_scenario()` 自动用作结构相似度分量。

## 这个攻击模式让我想起了什么？

有了嵌入之后，你可以问：「图谱中哪些节点在结构上与 APT29 最相似？」这不是关于共享的边，而是关于共享的*角色*。还有哪些节点在图中扮演着与 APT29 相同的位置？

```python
from semantica.kg import SimilarityCalculator

calc = SimilarityCalculator()

top5 = calc.find_most_similar(
    embeddings      = embeddings,
    query_embedding = embeddings["APT29"],
    top_k           = 5,
)

print("Nodes most similar to APT29 (by structural role):")
for node_id, score in top5:
    print(f"  [{score:.4f}]  {node_id}")
```

如果 `LAZARUS` 和 `APT38` 都以大于 0.85 的相似度出现在榜首，这值得写进你的分析师报告：这些组织在图中扮演着结构上完全相同的角色，即使传统归因把它们分开处理，也可能值得提出统一的追踪假设。

要直接比较两个节点：

```python
score = calc.cosine_similarity(embeddings["APT29"], embeddings["LAZARUS"])
print(f"Structural similarity APT29 ↔ LAZARUS: {score:.4f}")
```

如果想要一条无需预先计算全部嵌入的捷径：

```python
similar = graph.find_similar_nodes(
    "APT29",
    similarity_type = "structural",
    top_k           = 5,
)
for r in similar:
    print(f"  [{r['score']:.4f}]  {r['type']:20s}  {r['id']}")
```

## 预判下一步动作——链接预测

链接预测回答的是另一个问题：不是「哪些节点相似」，而是「哪些边*缺失*了？」图谱中两个节点之间可能缺少直接连接，不是因为这种连接不存在，而是因为你尚未观测到它。

实践中：你有 `APT29 → uses → SUNBURST` 和 `SUNBURST → targets → Windows Server 2019`。链接预测可能以高分给出 `APT29 → targets → Windows Server 2019`——这条连接由传递性隐含推出，但尚未被明确画出。

```python
from semantica.kg import LinkPredictor

predictor   = LinkPredictor()
predictions = predictor.predict_links(graph.to_dict(), top_k=10)

print("Predicted missing links:")
for node1, node2, score in predictions:
    print(f"  [{score:.4f}]  {node1}  →  {node2}")
```

高于 0.8 的分数值得分析师复核——这些不是随机结果，而是现有图谱的拓扑结构强烈隐含的边。低于 0.5 的分数是噪声。人工复核的最佳区间是 0.6–0.8：看似合理，但尚未确认。

<Info>
  链接预测也可通过 `DecisionQuery.predict_decision_relationships(decision_id, top_k)` 用于 `Decision` 节点。关于如何揭示过去决策之间的因果关系，参见[决策智能指南](decision-intelligence)。
</Info>

## 理解你的决策历史

当决策作为节点存储在图谱中时，`get_decision_insights()` 会为你提供横跨所有决策的分析视图：

```python
insights = graph.get_decision_insights()

print(f"Total decisions: {insights['total_decisions']}")
print(f"Mean confidence: {insights['confidence_stats']['mean']:.2f}")

print("\nBy category:")
for category, count in sorted(insights["categories"].items(), key=lambda x: -x[1]):
    print(f"  {category:<30} {count}")

print("\nBy outcome:")
for outcome, count in sorted(insights["outcomes"].items(), key=lambda x: -x[1]):
    print(f"  {outcome:<20} {count}")
```

置信度统计最能说明问题：如果平均置信度是 0.91，而最小值只有 0.34，说明有人在做出低置信度决策，却仍被记录为最终决定。这种差距值得在治理评审中标记出来。

`insights` 中的 `"advanced_analytics"` 键包含完整的 `analyze_graph_with_kg()` 结果——因此调用 `get_decision_insights()` 无需额外调用，就能得到完整的分析全貌。

<Tab title="国防 — CTI 威胁网络">

你的 SOC 刚刚把三路威胁情报订阅源合并成一张 CTI 图谱。在本周分析师简报之前，你需要为最危险的威胁行为者排名、识别隐藏的运营集群，并标记出尚未被正式追踪的隐含连接。

```python
from semantica.context import ContextGraph
from semantica.kg import CentralityCalculator, CommunityDetector, LinkPredictor
from semantica.visualization import AnalyticsVisualizer

graph = ContextGraph(
    advanced_analytics  = True,
    community_detection = True,
    node_embeddings     = True,
)
# (Populated from MISP/OTX/OSINT ingest)

# Full snapshot
report = graph.analyze_graph_with_kg()
print(f"Graph: {report['graph_metrics']['node_count']} nodes, "
      f"{report['graph_metrics']['edge_count']} edges")

# Rank brokers — who, if taken down, fragments the network?
calc     = CentralityCalculator()
measures = calc.calculate_all_centrality(graph.to_dict())
brokers  = measures["centrality_measures"]["betweenness"]["rankings"][:5]

print("\nTop 5 broker nodes (betweenness):")
for entry in brokers:
    print(f"  [{entry['score']:.4f}]  {entry['node']}")

# Find operational clusters
detector = CommunityDetector()
result   = detector.detect_communities(graph.to_dict(), algorithm="louvain")
print(f"\n{len(result['communities'])} clusters  "
      f"(modularity {result['modularity']:.3f})")

# Flag implied connections
predictor   = LinkPredictor()
predictions = predictor.predict_links(graph.to_dict(), top_k=5)
print("\nHigh-confidence implied connections:")
for n1, n2, score in predictions:
    if score > 0.7:
        print(f"  [{score:.3f}]  {n1}  →  {n2}")
```

<Tab title="安全 — 活跃事件">

事件处置进行期间，你的图谱已扩展到包含告警节点、受影响主机、横向移动边和已识别的恶意软件。你需要弄清影响范围：哪些主机是横向移动链条中的结构性中介节点？哪些连接尚未被正式记录？

```python
from semantica.context import ContextGraph
from semantica.kg import CentralityCalculator, LinkPredictor

graph = ContextGraph(advanced_analytics=True)
# (Populated from SIEM alert correlation and EDR telemetry)

calc     = CentralityCalculator()
measures = calc.calculate_all_centrality(graph.to_dict())

# Betweenness finds the pivot hosts — the ones lateral movement flows through
pivot_hosts = measures["centrality_measures"]["betweenness"]["rankings"][:5]
print("Pivot hosts (lateral movement brokers):")
for entry in pivot_hosts:
    print(f"  [{entry['score']:.4f}]  {entry['node']}")

# Identify the attacker's likely next targets
predictor   = LinkPredictor()
predictions = predictor.predict_links(graph.to_dict(), top_k=10)

print("\nLikely next lateral moves (predicted):")
for src, dst, score in predictions:
    if score > 0.65:
        print(f"  [{score:.3f}]  {src}  →  {dst}")

# Score a specific high-value target
dc_scores = graph.get_node_centrality("DC-PROD-01")
print(f"\nDomain Controller centrality:")
print(f"  Betweenness: {dc_scores['betweenness']:.4f}")
print(f"  PageRank:    {dc_scores['pagerank']:.4f}")
# High betweenness + high pagerank on a DC = confirmed pivot point
```

你的风险管理团队把交易对手关系建模为一张图谱：银行、SPV、风险敞口工具和监管实体，通过敞口、担保和所有权边连接起来。在季度压力测试之前，你需要识别哪些实体具有系统重要性——它们的倒闭会引发最广泛的连锁反应。

```python
from semantica.context import ContextGraph
from semantica.kg import CentralityCalculator, CommunityDetector

graph = ContextGraph(advanced_analytics=True, community_detection=True)
# (Populated from regulatory filings, trade repositories, and internal exposure data)

calc     = CentralityCalculator()
measures = calc.calculate_all_centrality(graph.to_dict())

# Eigenvector finds "too connected to fail" — entities connected to other
# high-centrality entities
systemic = measures["centrality_measures"]["eigenvector"]["rankings"][:5]
print("Systemically connected entities:")
for entry in systemic:
    print(f"  [{entry['score']:.4f}]  {entry['node']}")

# Betweenness finds contagion brokers — entities that, if they defaulted,
# would disconnect otherwise-separate parts of the exposure graph
brokers = measures["centrality_measures"]["betweenness"]["rankings"][:5]
print("\nContagion brokers:")
for entry in brokers:
    print(f"  [{entry['score']:.4f}]  {entry['node']}")

# Find exposure clusters — groups with dense mutual exposure
detector = CommunityDetector()
result   = detector.detect_communities(graph.to_dict(), algorithm="louvain")
print(f"\n{len(result['communities'])} exposure clusters  "
      f"(modularity {result['modularity']:.3f})")
```

## 常见陷阱

**把预测当作事实。**链接预测和相似度分数是概率性估计，不是已确认的关系。高的链接预测分数提示存在可能的连接，但在据此行动之前需要人工验证。

**重复实体。**把 "APT-29"、"APT29" 和 "Cozy Bear" 作为不同节点存在，会人为压低它们的中心性得分并割裂社区。运行分析之前先对实体去重，才能得到准确结果。

**命名不一致。**把 "ThreatActor"、"threat_actor" 和 "Actor" 混用作节点类型，会破坏按节点类型分组的分析。在你的各数据源之间使用一致的命名约定。

**过度解读分析结果。**介数中心性高的节点在你当前的图谱中结构上重要——但在现实世界中未必重要。分析揭示的是你数据中的模式，而不是关于领域的普遍真理。

**在过小的图谱上运行分析。**社区检测和中心性度量在拥有 100 个以上节点且连接密度足够的图谱上最有意义。低于该阈值的图谱，其结果可能无法提供可靠的洞见。

**图谱质量差。**重复实体、命名不一致和缺失的关系会直接影响分析准确性。运行分析之前先对数据去重和规范化——算法会放大图谱中存在的任何结构，包括噪声。

## 这些数字意味着什么

| 分数 | 它告诉你什么 |
| :--- | :--- |
| Betweenness > 0.15 | 关键中介节点——在任何归因或根因分析中，先调查这个节点 |
| Modularity > 0.4 | 社区是真实存在的，而非统计噪声——可以信任该聚类 |
| Modularity < 0.2 | 图谱过于稠密，在此层级上无法形成有意义的社区结构 |
| Embedding cosine similarity > 0.85 | 两个节点在结构上几乎相同——统一追踪的有力假设 |
| Link prediction score > 0.7 | 这条边几乎肯定存在——排入分析师确认队列 |
| Link prediction score 0.5–0.7 | 看似合理但不确定——当作假设而非事实对待 |
