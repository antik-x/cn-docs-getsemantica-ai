欢迎任何形式的贡献：代码、文档、测试与社区支持。每一份贡献都会在发布说明与 GitHub 贡献者列表中得到致谢。


## 快速开始

```bash
# Fork the repo on GitHub, then:
git clone https://github.com/your-username/semantica.git
cd semantica
pip install -e ".[dev]"
pytest
```

刚接触这个项目？从带 [`good-first-issue`](https://github.com/semantica-agi/semantica/labels/good-first-issue) 标签的任务开始：它们被限定为无需深入了解代码库、几个小时就能完成。


## 贡献方式

- **代码** —— 修复 bug、实现功能、优化性能，或使用插件注册表添加新的摄取器、解析器与导出器。
- **文档** —— 修正错别字、提升表达清晰度、补充缺失的示例、编写教程，或在模块演进时保持 API 参考的准确。
- **测试** —— 为未测试的模块或边界情况补充测试覆盖、用最小复现用例复现已报告的 bug，或提升跨平台可靠性。
- **社区** —— 在 GitHub Issues 与 Discussions 中回答问题、以建设性反馈评审 pull request，或通过博客文章与演讲传播 Semantica。


## 开发环境搭建

```bash
git clone https://github.com/your-username/semantica.git
cd semantica
pip install -e ".[dev]"
```

**代码风格工具：**

```bash
pytest                      # full test suite
black semantica/ tests/     # auto-format
isort semantica/ tests/     # sort imports
flake8 semantica/           # lint
```

风格约定：格式化用 **Black**，导入排序用 **isort**，代码检查用 **flake8**。三者都会在 CI 中运行。


## 报告问题

**Bug 报告**应包含：

- 实际发生了什么，以及你期望发生什么
- 复现问题的最少步骤
- 你的环境：Python 版本、操作系统、Semantica 版本（`python -c "import semantica; print(semantica.__version__)"`）

**功能请求**应包含：

- 你的具体使用场景
- 你希望 Semantica 做什么
- 为什么它能让广泛的用户受益，而不只是你的特定工作流


## Pull Request 检查清单

提交 PR 之前，请确认：

<Check>测试在本地通过：`pytest`</Check>
<Check>新功能附带文档，并含可运行的代码示例</Check>
<Check>代码遵循项目风格：Black、isort、flake8</Check>
<Check>提交信息清晰，说明*为什么*，而不只是*做了什么*</Check>
<Check>没有未解决的合并冲突</Check>


## 行为准则

所有贡献者都应遵循 [Contributor Covenant 行为准则](https://github.com/semantica-agi/semantica/blob/main/CODE_OF_CONDUCT.md)。请保持尊重、耐心与建设性——尤其是对待新成员。如发现违规行为，请以 `[CoC]` 为前缀开一个 issue 进行报告。
