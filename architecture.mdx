Semantica 围绕四层模块化架构构建。只导入你需要的部分：框架从不强迫你使用完整技术栈。每个组件都可独立替换，每一层都通过清晰的接口通信，没有隐藏耦合。

<Tabs>

<Tab title="第 1 层：摄取">

把任意来源的数据以统一的 `SourceDocument` 加载进流水线。

| 来源 | 模块 | 说明 |
| :------ | :------ | :----- |
| PDF、DOCX、PPTX、HTML、JSON、CSV | `ingest.FileIngestor` | 支持归档文件、递归目录扫描 |
| Parquet | `ingest.ParquetIngestor` | PyArrow、Hive 风格分区（v0.5.0） |
| XML | `ingest.XMLIngestor` | 对 XXE 安全的 lxml、XSD/DTD 校验（v0.5.0） |
| 网页 | `ingest.WebIngestor` | 可配置深度、链接过滤 |
| SQL / Snowflake / Databricks | `ingest.DBIngestor` / `ingest.SnowflakeIngestor` / `ingest.DatabricksIngestor` | 自定义 SQL、Schema 自省、Unity Catalog 血缘 |
| Kafka / 流 | `ingest.StreamIngestor` | 实时订阅源摄取 |
| 电子邮件 | `ingest.EmailIngestor` | IMAP/SMTP，支持附件抽取 |
| 代码仓库 | `ingest.RepoIngestor` | Git 仓库、代码结构 |
| MCP | `ingest.MCPIngestor` | 模型上下文协议（MCP）来源 |

</Tab>

<Tab title="第 2 层：处理">

把原始文本转换为结构化、信息丰富的文档，为知识存储摄取做好准备。

| 步骤 | 模块 | 作用 |
| :---- | :------ | :------------ |
| 解析 | `parse.DocumentParser` / `parse.DoclingParser` | 文本 + 版面抽取、表格检测 |
| 规范化 | `normalize` | 规范形式、日期/名称标准化、编码修复 |
| 抽取 | `semantic_extract` | 命名实体识别（NER）、关系抽取、事件检测、三元组（Triplet） |
| 构建 | `kg.GraphBuilder` | 实体合并、边构建、图组装 |
| 质量保障 | `deduplication`, `conflicts` | 重复检测、冲突解决、校验 |

</Tab>

<Tab title="第 3 层：智能">

为检索和推理提供动力的持久化知识存储与嵌入（Embedding）基础设施。

| 组件 | 模块 | 描述 |
| :--------- | :------ | :----------- |
| 知识图谱（Knowledge Graph） | `kg` | 图构建、时序模型、图分析、距离智能 |
| 向量存储 | `vector_store` | pgvector、Qdrant、Weaviate、Pinecone：语义相似度检索 |
| 本体 | `ontology` | OWL/RDFS 建模、SHACL 校验、本体对齐 |
| 三元组存储 | `triplet_store` | RDF 三元组存储与 SPARQL 查询 |
| 嵌入 | `embeddings` | Sentence-Transformers、FastEmbed、OpenAI、BGE |
| 时序 | `kg.TemporalKnowledgeGraph` | `valid_from` / `valid_until`、Allen 区间代数（v0.4.0） |

</Tab>

<Tab title="第 4 层：应用">

为下游使用场景消费知识图谱和向量存储。

| 使用场景 | 模块 | 描述 |
| :-------- | :------ | :----------- |
| GraphRAG | `context.AgentContext` | 面向 LLM 的图谱锚定检索 |
| 智能体记忆 | `context.ContextGraph` | 跨智能体运行的持久语义记忆 |
| 决策追踪 | `context.AgentContext` | 记录、追踪并审计每个智能体决策 |
| Ontology Hub | `explorer` | 可视化编辑器、SHACL Studio、对齐 UI（v0.5.0） |
| 多智能体 | `integrations.agno` | 共享上下文、团队级记忆、KG 工具集 |
| 可视化 | `visualization` | 交互式 HTML 图谱、嵌入图、时序视图 |
| 导出 | `export` | RDF、Parquet、ArangoDB AQL、OWL、CSV、Arrow |
| 推理 | `reasoning` | 前向链、Rete、Datalog、SPARQL、溯因 |

</Tab>

## 扩展点

每一层都暴露一个基于注册表的扩展点。注册自定义实现后，它们即可参与完整流水线，核心代码零改动。

<CodeGroup>

```python Custom Ingestor
from semantica.ingest.registry import method_registry

def custom_file_ingestor(source):
    # Return a list of document dicts with 'text', 'metadata', 'source'
    return [{"text": "...", "metadata": {}, "source": source}]

# Register under the "file" task category with a unique name
method_registry.register("file", "my_custom_format", custom_file_ingestor)

available = method_registry.list_all("file")
```

```python Custom Extractor
from semantica.semantic_extract.registry import method_registry

def custom_entity_extractor(text, config=None):
    # Return a list of entity dicts with 'text', 'type', 'confidence'
    return [{"text": "...", "type": "CUSTOM_TYPE", "confidence": 0.9}]

# Register under the "entity" extraction task
method_registry.register("entity", "my_extractor", custom_entity_extractor)
```

```python Custom Plugin
from semantica.core import PluginRegistry

class MyPlugin:
    def process(self, graph, config):
        # Modify the graph in place and return it
        return graph

registry = PluginRegistry()
registry.register_plugin("my_plugin", MyPlugin, version="1.0.0")
```

</CodeGroup>


## 设计决策

<AccordionGroup>

<Accordion title="模块化：只使用你需要的" icon="puzzle-piece">

每个组件都可独立运行。`NERExtractor` 无需图存储即可运行。`VectorStore` 无需决策追踪即可运行。框架从不强迫完整技术栈实例化：只为导入的东西买单。

</Accordion>

<Accordion title="可插拔：扩展而不修改核心" icon="plug">

自定义摄取器、抽取器、校验器和导出器都遵循相同的基类模式。通过 `PluginRegistry` 注册它们，它们即可参与完整流水线——包括溯源（Provenance）追踪、重试策略和并行执行——而核心代码零改动。

</Accordion>

<Accordion title="默认开启溯源" icon="link">

血缘追踪内建于最底层的图构建。每个节点和边都携带一个 `source_id`，指向来源文档、抽取方法和时间戳。无需主动开启：溯源始终在线。

</Accordion>

<Accordion title="配置优于约定" icon="sliders">

集中式 `ConfigManager`，支持环境变量覆盖。没有魔法默认值：所有行为都显式且可覆盖。适合开发、预发布和生产环境需要不同后端的多环境部署。

</Accordion>

</AccordionGroup>


## 性能特性

| 特性 | 机制 |
| :-------------- | :--------- |
| **并行执行** | `Pipeline(workers=N)`，每个阶段的 worker 数可配置 |
| **增量处理** | 增量图更新：新数据无需全量重算 |
| **流式摄取** | 处理大型语料，无需把所有内容载入内存 |
| **后端灵活** | 把内存型 NetworkX 换成 Neo4j / FalkorDB，API 无需改动 |
| **去重 v2** | `blocking_v2`、`hybrid_v2`、`semantic_v2`：比 v1 快至 7 倍 |
| **索引检索** | Explorer 检索在 118k 节点上 0.004 毫秒（v0.5.0） |
